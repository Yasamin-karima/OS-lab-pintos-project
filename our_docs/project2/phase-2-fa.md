# پروژه ۲ پینتوس: برنامه‌های کاربر (User Programs) — گزارش فنی و راهنمای جامع فاز ۲
## اعتبارسنجی دسترسی به حافظه کاربر و مدیریت امن نقص صفحه (Page Fault)

---

## ۱. اهداف کلی پروژه و اهداف این فاز (Project & Phase Objectives)

### ۱.۱ اهداف کلان پروژه ۲ پینتوس (User Programs)
در پروژه ۱ پینتوس، تمامی ریسه‌ها (Threads) به عنوان کدهای معتمد در فضای هسته (Kernel Mode یا Ring 0) و بدون تفکیک حافظه اجرا می‌شدند. در پروژه ۲، سیستم‌عامل گامی اساسی به سوی یک سیستم‌عامل واقعی برمی‌دارد و امکان بارگذاری و اجرای **برنامه‌های کاربر (User Programs)** در سطح دسترسی غیرممتاز سخت‌افزاری (Ring 3 معماری x86) را فراهم می‌سازد. اهداف کلان این معماری عبارتند از:
1. **جداسازی و حفاظت (Isolation & Protection):** یک برنامه کاربر غیرمعتمد هرگز نباید بتواند به حافظه اختصاصی هسته یا داده‌های سایر پردازه‌ها دستبرد بزند، در اجرای آن‌ها تداخل ایجاد کند یا سیستم‌عامل را دچار Kernel Panic نماید.
2. **درگاه فراخوانی‌های سیستمی (System Calls Gateway):** فراهم آوردن یک مسیر ارتباطی کنترل‌شده و امن از طریق وقفه نرم‌افزاری `int $0x30` تا پردازه‌ها بتوانند سرویس‌های هسته (مانند ورودی/خروجی، کنترل پردازه و مدیریت فایل) را درخواست کنند.
3. **آزادسازی امن منابع (Resource Reclamation):** بازپس‌گیری کامل تمام حافظه‌ها، قفل‌ها و توصیف‌کننده‌های فایل به هنگام خروج عادی یا کشته شدن پردازه به دلیل خطای حافظه.

### ۱.۲ اهداف معماری فاز ۲ (Architectural Goals of Phase 2)
در فاز ۱، سازوکار ارسال آرگومان‌ها در پشته کاربر (`setup_stack`) و همگام‌سازی پایه خروج و انتظار پردازه‌ها (`exit`، `wait`، `exec`، `halt`) پیاده‌سازی شد. با این حال، نسخه پایه پینتوس فاقد هرگونه بررسی و اعتبارسنجی اشاره‌گرهای ارسال‌شده از سوی کاربر بود. یک برنامه کاربر خرابکار یا دارای باگ می‌توانست اشاره‌گرهای نامعتبری را به هسته تحویل دهد:
- اشاره‌گر تهی (`NULL` یا `0x00000000`).
- آدرس‌های نگاشت‌نشده در فضای آدرس مجازی پراکنده (Unmapped Virtual Address Space).
- آدرس‌های متعلق به فضای هسته (`>= PHYS_BASE` که در پینتوس برابر `0xc0000000` است).
- ساختارها، متغیرهای ۴ بایتی، یا رشته‌هایی که بایت ابتدایی آن‌ها معتبر است اما در ادامه از مرز صفحه عبور کرده و وارد صفحات نگاشت‌نشده یا فضای هسته می‌شوند (`sc-boundary`، `sc-boundary-2`، `sc-boundary-3`).
- اشاره‌گر پشته دستکاری‌شده یا نامعتبر (`%esp`) که به خارج از حافظه کاربر اشاره می‌کند (`sc-bad-sp`، `sc-bad-arg`).

هدف معماری **فاز ۲** پیاده‌سازی **اعتبارسنجی نفوذناپذیر حافظه کاربر (Bulletproof User Memory Validation)** و **مهار امن خطاهای نقص صفحه (Safe Page Fault Handling)** است:
1. تک‌تک بایت‌های اشاره‌گرها، بافرها، رشته‌ها و آرگومان‌های پشته که توسط پردازه کاربر ارسال می‌شوند، باید قبل از هرگونه خواندن یا نوشتن توسط هسته اعتبارسنجی شوند.
2. در صورت کشف هرگونه آدرس نامعتبر، دسترسی غیرمجاز به حافظه هسته، یا نقض مجوز دسترسی، هسته باید **تنها** پردازه خاطی را با کد وضعیت `-1` (چاپ خروجی استاندارد `<process_name>: exit(-1)`) خاتمه دهد.
3. سیستم‌عامل تحت هیچ شرایطی نباید به دلیل خطای برنامه کاربر وارد حالت Kernel Panic شده یا حافظه هسته نشت کند.

| `bad-write` | برنامه کاربر سعی می‌کند در یک آدرس نگاشت‌نشده مقدار بنویسد. | مهار ایمن خطا در وقفه `#PF` و خروج با کد `-1`. |
| `bad-write2` | برنامه کاربر سعی می‌کند در سگمنت کد که فقط‌خواندنی (Read-Only) است بنویسد. | رخداد خطای نقض دسترسی (Rights Violation) و خروج با کد `-1`. |
| `bad-jump` | برنامه کاربر تلاش می‌کند به آدرس `0x00000000` پرش کرده و آن را به عنوان دستورالعمل اجرا کند. | مهار خطای اجرای دستور از صفحه نگاشت‌نشده و خروج با کد `-1`. |
| `bad-jump2` | برنامه کاربر تلاش می‌کند به یک آدرس نامعتبر پرش کند. | مهار ایمن خطای واکشی دستورالعمل و خروج با کد `-1`. |
| `exec-bad-ptr` | ارسال یک اشاره‌گر نامعتبر (`0x20101234`) به عنوان رشته نام دستور به فراخوانی سیستمی `exec`. | اعتبارسنجی رشته مانع از خواندن شده و پردازه با `-1` خارج می‌شود. |
| `write-bad-ptr` | ارسال بافر نامعتبر (`0x10123420`) به فراخوانی سیستمی `write`. | اعتبارسنجی بافر مانع از ارجاع هسته شده و پردازه با `-1` خارج می‌شود. |

#### ۲.۱.۲ تابع کمکی خاتمه پردازه خاطی: `terminate_invalid_process()` (خطوط ۲۳ تا ۲۹)
```c
static void
terminate_invalid_process (void)
{
  struct thread *cur = thread_current ();
  cur->exit_status = -1;
  thread_exit ();
}
```
- **شماره خطوط:** خطوط ۲۳ تا ۲۹ در فایل `src/userprog/syscall.c`.
- **علت ضرورت:** در پینتوس پایه، هنگام بروز خطای حافظه یا فراخوانی نامعتبر، یا برنامه نادیده گرفته می‌شد یا هسته دچار Kernel Panic می‌گردید. طبق مستندات پروژه ۲، هرگونه تخلف حافظه کاربر باید بلافاصله پردازه را با کد وضعیت خروج `-1` نابود کند.
- **اثر اجرایی:** متغیر `exit_status` پردازه جاری روی `-1` تنظیم شده و `thread_exit()` صدا زده می‌شود. این تابع در ادامه `process_exit()` را فراخوانی می‌کند که پیام استاندارد `"<name>: exit(-1)\n"` را چاپ کرده، والد منتظر را از طریق `sema_up` بیدار می‌سازد، منابع را بازپس می‌گیرد و جدول صفحه را نابود می‌کند، بدون این‌که هسته خاموش یا متوقف شود.

#### ۲.۱.۳ اعتبارسنجی تک‌آدرس: `validate_user_addr()` (خطوط ۳۱ تا ۳۸)
```c
static void
validate_user_addr (const void *uaddr)
{
  if (uaddr == NULL || !is_user_vaddr (uaddr))
    terminate_invalid_process ();
  if (pagedir_get_page (thread_current ()->pagedir, uaddr) == NULL)
    terminate_invalid_process ();
}
```
- **شماره خطوط:** خطوط ۳۱ تا ۳۸ در فایل `src/userprog/syscall.c`.
- **علت ضرورت:** پیش از این‌که هسته هر بایتی از حافظه کاربر را دی‌فرنس کند، باید ۳ شرط احراز شود:
  1. `uaddr != NULL`: آدرس تهی نباشد.
  2. `is_user_vaddr(uaddr)`: آدرس در محدوده فضای مجازی کاربر باشد (`uaddr < PHYS_BASE`). اگر این شرط نباشد، پردازه کاربر می‌تواند آدرس‌های داخلی داده‌های هسته (مانند جداول زمان‌بندی یا ساختارهای کنترلی) را ارسال کند و هسته را فریب دهد.
  3. `pagedir_get_page(...) != NULL`: آدرس مجازی مورد نظر حتماً در جدول صفحه پردازه جاری نگاشت شده و دارای بیت Present باشد. خواندن آدرس نگاشت‌نشده در فضای هسته، باعث رخداد Kernel Page Fault می‌شد.
- **اثر اجرایی:** در صورت نقض هر یک از شرایط، کنترل برنامه فوراً به `terminate_invalid_process()` منتقل شده و پردازه خاطی کشته می‌شود.

#### ۲.۱.۴ اعتبارسنجی محدوده و عبور از مرز صفحه: `validate_user_range()` (خطوط ۴۰ تا ۶۹)
```c
static void
validate_user_range (const void *uaddr, size_t size)
{
  if (uaddr == NULL)
    terminate_invalid_process ();

  if (size == 0)
    {
      if (!is_user_vaddr (uaddr))
        terminate_invalid_process ();
      return;
    }

  const uint8_t *start = (const uint8_t *) uaddr;
  const uint8_t *end = start + size - 1;

  if (end < start)
    terminate_invalid_process ();

  if (!is_user_vaddr (start) || !is_user_vaddr (end))
    terminate_invalid_process ();

  const uint8_t *page = (const uint8_t *) pg_round_down (start);
  while (page <= end)
    {
      if (pagedir_get_page (thread_current ()->pagedir, page) == NULL)
        terminate_invalid_process ();
      page += PGSIZE;
    }
}
```
- **شماره خطوط:** خطوط ۴۰ تا ۶۹ در فایل `src/userprog/syscall.c`.
- **علت ضرورت:**
  1. **خطر عبور از مرز صفحه (Cross-Page Boundary):** اگر متغیری ۴ بایتی یا بافری با طول مشخص در انتهای یک صفحه قرار گیرد (مثلاً بایت ۴۰۹۴ از یک صفحه ۴۰۹۶ بایتی)، بررسی آدرس بایت اول به تنهایی کافی نیست؛ چرا که بایت‌های دوم، سوم یا چهارم ممکن است وارد صفحه بعدی شوند که نگاشت نشده یا متعلق به هسته است (`sc-boundary-3`).
  2. **سرریز محاسباتی اعداد بدون علامت (Integer Overflow):** اگر کاربری آدرس `0xfffffff0` با اندازه `0x20` بفرستد، جمع ساده ریاضی سرریز کرده و آدرس انتهایی دور می‌زند. شرط `if (end < start)` این سرریز را تشخیص داده و پردازه را متوقف می‌کند.
  3. **عملیات با اندازه صفر (`write-zero`):** در نوشتن یا خواندن با طول صفر، آدرس بافر نباید `NULL` یا در فضای هسته باشد، اما هیچ بایتی نیاز به دی‌فرنس ندارد.
- **اثر اجرایی:** حلقه `while (page <= end)` با گام‌های ۴۰۹۶ بایتی (`PGSIZE`) تمامی فریم‌های صفحه‌ای را که بازه `[start, end]` در آن‌ها گسترده شده است، تک‌به‌تک از طریق جدول صفحه بررسی می‌کند. در صورت عدم نگاشت حتی یک صفحه، پردازه بلافاصله نابود می‌شود.

#### ۲.۱.۵ اعتبارسنجی رشته با طول نامشخص: `validate_user_string()` (خطوط ۷۱ تا ۸۵)
```c
static void
validate_user_string (const char *str)
{
  if (str == NULL)
    terminate_invalid_process ();

  const char *p = str;
  while (true)
    {
      validate_user_addr (p);
      if (*p == '\0')
        break;
      p++;
    }
}
```
- **شماره خطوط:** خطوط ۷۱ تا ۸۵ در فایل `src/userprog/syscall.c`.
- **علت ضرورت:** رشته‌های ارسالی کاربر (مانند نام فایل در `exec()`) طول از پیش مشخصی ندارند. اگر هسته مستقیماً `strlen()` را فراخوانی می‌کرد، یک رشته نامعتبر و فاقد کاراکتر تهی (`\0`) می‌توانست مرز حافظه نگاشت‌شده را رد کرده و هسته را با نقص صفحه متوقف کند.
- **اثر اجرایی:** این تابع به صورت بایتی و قدم‌به‌قدم، ابتدا آدرس بایت جاری `p` را با `validate_user_addr(p)` تایید می‌کند و **تنها پس از احراز صحت**، مقدار `*p` را می‌خواند. اگر رشته بدون کاراکتر تهی به پایان صفحه نگاشت‌شده یا مرز `PHYS_BASE` برسد، پیش از هرگونه دسترسی غیرمجاز متوقف می‌شود.

#### ۲.۱.۶ اعتبارسنجی آرگومان‌های پشته در `syscall_handler()` (خطوط ۸۷ تا ۱۴۹)
```c
static void
syscall_handler (struct intr_frame *f) 
{
  validate_user_range (f->esp, sizeof (uint32_t));
  int syscall_num = *(int *) f->esp;

  switch (syscall_num)
    {
    case SYS_HALT:
      shutdown_power_off ();
      break;

    case SYS_EXIT:
      validate_user_range ((const uint8_t *) f->esp + 4, sizeof (int));
      {
        int status = *((int *) f->esp + 1);
        struct thread *cur = thread_current ();
        cur->exit_status = status;
        thread_exit ();
      }
      break;

    case SYS_EXEC:
      validate_user_range ((const uint8_t *) f->esp + 4, sizeof (char *));
      {
        const char *cmd_line = (const char *) *((uintptr_t *) f->esp + 1);
        validate_user_string (cmd_line);
        f->eax = process_execute (cmd_line);
      }
      break;

    case SYS_WAIT:
      validate_user_range ((const uint8_t *) f->esp + 4, sizeof (tid_t));
      {
        tid_t child_tid = *((int *) f->esp + 1);
        f->eax = process_wait (child_tid);
      }
      break;

    case SYS_WRITE:
      validate_user_range ((const uint8_t *) f->esp + 4, sizeof (int) * 3);
      {
        int fd = *((int *) f->esp + 1);
        const void *buffer = (const void *) *((uintptr_t *) f->esp + 2);
        unsigned size = *((unsigned *) f->esp + 3);
        validate_user_range (buffer, size);
        if (fd == 1)
          {
            putbuf (buffer, size);
            f->eax = size;
          }
        else
          {
            f->eax = 0;
          }
      }
      break;

    default:
      terminate_invalid_process ();
      break;
    }
}
```
- **شماره خطوط:** خطوط ۸۷ تا ۱۴۹ در فایل `src/userprog/syscall.c`.
- **علت ضرورت:**
  - بررسی `f->esp` به اندازه ۴ بایت تضمین می‌کند که شماره فراخوانی سیستمی کاملاً در حافظه نگاشت‌شده کاربر قرار دارد (`sc-bad-sp` و `sc-boundary-3`).
  - برای هر فراخوانی سیستمی مشخص، خانه‌های آرگومان در پشته (`f->esp + 4` و بعد از آن) قبل از خواندن، تحت اعتبارسنجی دقیق قرار می‌گیرند. به عنوان نمونه در `sc-bad-arg`، پشته روی `0xbffffffc` قرار دارد؛ آرگومان در `f->esp + 4` آدرس `0xc0000000` است که به فضای هسته تجاوز کرده و پیش از دی‌فرنس شناسایی و مسدود می‌شود.
  - در `SYS_WRITE`، خود بافر نیز به طور کامل با `validate_user_range(buffer, size)` بررسی می‌شود تا بافرهای نامعتبر به تابع `putbuf()` نرسند.
- **اثر اجرایی:** مسدودسازی قطعی هرگونه اشاره‌گر نامعتبر، حفظ ثبات هسته و تأمین پیش‌نیازهای امنیتی سیستم‌عامل.

- **علت ضرورت:** استفاده از ماکروی `is_user_vaddr()` جهت تمایز آدرس‌های کاربر از هسته.

#### ۲.۲.۲ مهار خطای نقص صفحه در `page_fault()` (خطوط ۱۴۷ تا ۱۵۷)
```c
  /* Determine cause. */
  not_present = (f->error_code & PF_P) == 0;
  write = (f->error_code & PF_W) != 0;
  user = (f->error_code & PF_U) != 0;

  if (user || is_user_vaddr (fault_addr))
    {
      thread_current ()->exit_status = -1;
      thread_exit ();
    }

  /* To implement virtual memory, delete the rest of the function
     body, and replace it with code that brings in the page to
     which fault_addr refers. */
```
- **شماره خطوط:** خطوط ۱۴۷ تا ۱۵۷ در فایل `src/userprog/exception.c`.
- **علت ضرورت:** در نسخه پایه پینتوس، تابع `page_fault()` بلافاصله تابع `kill(f)` را صدا می‌زد که باعث Kernel Panic و توقف کل سیستم می‌شد.
  - زمانی که یک دستورالعمل در کد کاربر خطای حافظه ایجاد کند (مانند خواندن `NULL` در `bad-read` یا نوشتن در کد در `bad-write2`)، بیت `user` در کد خطای پردازنده برابر `true` است.
  - اگر در جریان یک فراخوانی سیستمی، هسته به آدرس کاربر ارجاع دهد و خطا رخ دهد، `user == false` خواهد بود اما آدرس خطا متعلق به فضای کاربر است (`is_user_vaddr(fault_addr)`).
- **اثر اجرایی:** در هر دو حالت، این رخداد به عنوان تخلف حافظه پردازه کاربر شناخته می‌شود. پردازه با کد خروج `-1` کشته شده و هسته به کار خود با سایر پردازه‌ها ادامه می‌دهد. تنها در صورتی که یک خطای واقعی در کدهای هسته روی حافظه اختصاصی هسته رخ دهد (`!user && !is_user_vaddr(fault_addr)`)، هسته متوقف می‌شود.

## ۳. آموزش مفاهیم سیستم‌عامل مرتبط با این فاز (Operating System Concepts & Deep-Dive Study Guide)

### ۳.۱ تفکیک فضای کاربر از هسته و سطوح دسترسی سخت‌افزاری (Hardware Privilege Rings)

پردازنده‌های معماری x86 دارای ۴ سطح حفاظتی موسوم به Ring هستند که پینتوس (مشابه لینوکس) از سطوح ۰ و ۳ آن استفاده می‌کند:
- **Ring 0 (حالت هسته / Kernel Mode):** دسترسی تام به تمامی دستورالعمل‌های ممتاز ماشین (مانند دستکاری رجیسترهای کنترلی `%cr0`، `%cr2`، `%cr3` و جداول توصیف‌گر وقفه و سگمنت `lgdt`، `lidt`) و امکان دسترسی به کل فضای حافظه مجازی.
- **Ring 3 (حالت کاربر / User Mode):** اجرای برنامه‌های کاربر با محدودیت سخت‌افزاری. اجرای دستورات ممتاز سبب بروز خطای General Protection Fault (`#GP`) می‌شود و دسترسی به صفحات حافظه‌ای که بیت کاربر/سرپرست آن‌ها فعال نیست (`U/S = 0`) ممنوع است.

```
+-------------------------------------------------------------------+ 0xFFFFFFFF
|                                                                   |
|                   فضای آدرس مجازی هسته (Kernel Space)               |
|                   (سطح دسترسی: فقط Ring 0، فلگ U/S = 0)           |
|                                                                   |
+-------------------------------------------------------------------+ 0xC0000000 (PHYS_BASE)
|                                                                   |
|                   فضای آدرس مجازی کاربر (User Space)              |
|                   (سطح دسترسی: مجاز برای Ring 3، فلگ U/S = 1)      |
|                                                                   |
|   - پشته کاربر (User Stack - رشد به سمت پایین از PHYS_BASE)        |
|   - فضای خالی نگاشت‌نشده (Sparse Address Space)                   |
|   - بخش‌های کد و داده برنامه (بارگذاری‌شده از فایل ELF)          |
|   - صفحه صفر محافظت‌شده (0x00000000 تا 0x00000FFF نگاشت‌نشده)     |
+-------------------------------------------------------------------+ 0x00000000
```

هنگامی که پردازه دستورالعمل `int $0x30` را صادر می‌کند:
1. پردازنده سخت‌افزاری سطح دسترسی را از Ring 3 به Ring 0 ارتقا می‌دهد.
2. پشته جاری را به پشته هسته ریسه (ذخیره‌شده در TSS) تغییر می‌دهد.
3. رجیسترهای `%ss`، `%esp`، `%eflags`، `%cs` و `%eip` حالت کاربر را در پشته هسته ذخیره می‌کند.
4. ساختار `struct intr_frame` ایجاد شده و کنترل به `syscall_handler()` سپرده می‌شود.

**نکته کلیدی امنیتی:** با ورود به Ring 0، سخت‌افزار پردازنده دیگر مانع از دسترسی هسته به آدرس‌های فضای هسته نمی‌شود. بنابراین اگر برنامه کاربر یک اشاره‌گر به فضای هسته تحویل دهد و هسته آن را مستقیماً دی‌فرنس کند، برنامه کاربر توانسته است محدودیت‌های سخت‌افزاری را دور بزند! اعتبارسنجی در `syscall.c` ضامن خنثی‌سازی این تهدید است.

### ۳.۲ ساختار جدول صفحه دوسطحی (Two-Level Paging System)

در معماری 32 بیتی x86 با صفحه‌بندی استاندارد 4KB، هر آدرس مجازی ۳۲ بیتی از سه بخش تشکیل می‌شود:

```
                  آدرس مجازی ۳۲ بیتی (Virtual Address)
 31                  22 21                  12 11                   0
+----------------------+----------------------+----------------------+
|  اندیس دایرکتوری صفحه |   اندیس جدول صفحه     |     آفست درون صفحه   |
|  Page Directory Index|   Page Table Index   |      Byte Offset     |
|      (۱۰ بیت)        |       (۱۰ بیت)       |       (۱۲ بیت)       |
+----------------------+----------------------+----------------------+
           |                      |                      |
           v                      |                      |
     دایرکتوری صفحه                v                      |
   +---------------+          جدول صفحه                  |
   |      PDE      |-----> +---------------+             |
   +---------------+       |      PTE      |----+        |
   |      ...      |       +---------------+    |        |
                           |      ...      |    |        |
                                                v        v
                                            فریم فیزیکی حافظه
                                           +-------------------+
                                           |     داده واقعی    |
                                           +-------------------+
```

- **رجیستر `%cr3`:** آدرس فیزیکی ریشه دایرکتوری صفحه پردازه جاری را نگه می‌دارد.
- **ورودی دایرکتوری صفحه (PDE):** ۱۰ بیت بالای آدرس یکی از ۱۰۲۴ جدول صفحه ممکن را انتخاب می‌کند.
- **ورودی جدول صفحه (PTE):** ۱۰ بیت میانی یکی از ۱۰۲۴ فریم فیزیکی (هر کدام ۴ کیلوبایت) را معین می‌سازد.
- **آفست (Offset):** ۱۲ بیت پایانی بایت دقیق را در فریم ۴۰۹۶ بایتی مشخص می‌کند.

تابع `pagedir_get_page(pd, uaddr)` این پیمایش را در نرم‌افزار شبیه‌سازی می‌کند. اگر PDE یا PTE موجود نباشد یا فلگ حضور (`PTE_P`) صفر باشد، مقدار `NULL` بازگردانده می‌شود که نشانگر عدم نگاشت حافظه است.

### ۳.۳ مکانیزم سخت‌افزاری وقفه ۱۴: نقص صفحه (Interrupt 14 / Page Fault)

هنگامی که دسترسی غیرمجاز یا نگاشت‌نشده رخ می‌دهد، پردازنده وقفه ۱۴ را صادر می‌کند:
1. **ثبت آدرس خطا در `%cr2`:** آدرس مجازی دقیق ایجادکننده خطا بلافاصله در رجیستر کمکی `%cr2` ذخیره می‌شود.
2. **پوش کردن کد خطا (Error Code):**
   - بیت ۰ (`PF_P`): اگر صفر باشد، صفحه اصلاً در حافظه حاضر نبوده است (Not-Present)؛ اگر یک باشد، نقض مجوز رخ داده است (مثلاً تلاش برای نوشتن در صفحه فقط‌خواندنی).
   - بیت ۱ (`PF_W`): صفر برای تلاش خواندن و یک برای تلاش نوشتن.
   - بیت ۲ (`PF_U`): صفر اگر خطا در حین اجرای کد هسته رخ داده و یک اگر در حین اجرای کد کاربر بوده است.

```
                      وقوع وقفه سخت‌افزاری نقص صفحه (#PF)
                                     |
                                     v
                       خواندن آدرس خطا از %cr2
                     خواندن کد خطای خطا از f->error_code
                                     |
                                     v
                       آیا خطا منشأ کاربری دارد؟
                       (user == true || is_user_vaddr(fault_addr))
                                  /      \
                            بله  /        \  خیر
                                v          v
                 thread_current()->exit_status = -1;    توقف سیستم / Kernel Panic
                 thread_exit();                        (خطای واقعی در حافظه هسته)
                                |
                                v
                 چاپ پیام "<name>: exit(-1)"
                 آزادسازی منابع و اعلام به والد
```

### ۳.۴ خطرات و مخاطرات عبور از مرز صفحه (Page Boundary Hazards)

در سیستم‌عامل‌های ۳۲ بیتی، متغیرهای اساسی مانند اعداد صحیح و اشاره‌گرها ۴ بایتی هستند. فرض کنید یک متغیر ۴ بایتی در مرز انتهای یک صفحه قرار گرفته باشد:

```
حالت اول: آزمون sc-boundary-2 (آرگومان تقسیم‌شده میان دو صفحه معتبر)
مرز صفحه در 0xBFFFF000:
   صفحه ۱ (معتبر - کاربر):   ... [بایت -۳] [بایت -۲] [بایت -۱] |
   صفحه ۲ (معتبر - کاربر):                                     | [بایت ۰] ...
   آرگومان فراخوانی = ۴ بایت [-3, -2, -1, 0].
   هر دو صفحه معتبرند -> تابع validate_user_range هر دو صفحه را تأیید کرده و فراخوانی موفق می‌شود!

حالت دوم: آزمون sc-boundary-3 (سرریز به صفحه نگاشت‌نشده نامعتبر)
مرز صفحه در 0xBFFFF000:
   صفحه ۱ (معتبر - کاربر):   ... [بایت ۰ (معتبر)] |
   صفحه ۲ (نگاشت‌نشده!):                          | [بایت ۱] [بایت ۲] [بایت ۳] ...
   شماره فراخوانی سیستمی = ۴ بایت [0, 1, 2, 3].
   بررسی ساده بایت اول به اشتباه اجازه خواندن می‌دهد و منجر به کرش هسته می‌شود.
   تابع validate_user_range بازه کامل ۴ بایت را بررسی کرده و خطای صفحه ۲ را کشف و پردازه را با -1 می‌کشد!

حالت سوم: آزمون sc-bad-arg (نفوذ به فضای هسته)
مرز PHYS_BASE در 0xC0000000:
   فضای کاربر (< PHYS_BASE):  ... [0xBFFFFFFC] (شماره فراخوانی SYS_EXIT)
   فضای هسته (>= PHYS_BASE):      [0xC0000000] (آرگومان کد خروج)
   اشاره‌گر پشته در فضای کاربر است، اما آرگومان آن روی مرز هسته افتاده است.
   بررسی آرگومان نشان می‌دهد آدرس >= PHYS_BASE است -> پردازه فوراً متوقف شده و با -1 خارج می‌شود!
```

### ۳.۶ اشتباهات و باگ‌های رایج در پیاده‌سازی فاز ۲

1. **خطای محاسباتی آفست انتهایی (Off-by-One Error):**
   محاسبه انتهای بازه به صورت `end = start + size` به جای `start + size - 1`. اگر بافری تا آخرین بایت یک صفحه (بایت ۴۰۹۵) ادامه یابد، `start + size` به بایت صفرم صفحه بعدی اشاره می‌کند؛ اگر صفحه بعدی نگاشت نشده باشد، بافر معتبر کاربر به اشتباه رد می‌شود.
2. **عدم مهار سرریز محاسباتی اعداد بدون علامت:**
   نادیده گرفتن شرط `if (end < start)`. مقادیر آدرس بزرگ با اندازه مثبت می‌توانند دور بزنند و شروط `end < PHYS_BASE` را فریب دهند.
3. **اعتبارسنجی ناکافی در فراخوانی‌های رشته‌ای:**
   در فراخوانی‌هایی مانند `exec`، صرفاً بررسی اشاره‌گر پشته کافی نیست؛ تک‌تک کاراکترهای رشته در حافظه باید تا زمان رسیدن به کاراکتر پایانی `\0` از نظر نگاشت صفحه بررسی شوند.
4. **تولید خروجی‌های غیراستاندارد یا پانیک هسته:**
   استفاده از `printf`های متفرقه دیباگ یا فراخوانی `PANIC()` باعث مردود شدن در اسکریپت‌های تست پینتوس می‌شود. قالب خروجی دقیقاً باید از ساختار `printf("%s: exit(%d)\n", ...)` پیروی کند.
